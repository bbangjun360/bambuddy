# Purpose

Add a default-off SwapMod canary preflight workflow that packages one reviewed
WP-065 dry-run candidate for human canary review without executing printer
commands.

This Work Package does not send G-code, upload files, start prints, dispatch
queue work, call the scheduler, connect to Bambu MQTT or FTPS, mutate ERP,
Obico, or bed automation state, retry, resume after restart, or start the next
print.

# Current Behavior

WP-065 can summarize redacted SwapMod candidate blocks from one original 3MF
and one SwapMod 3MF. It does not prepare a canary package, verify a candidate
against a target printer, require SwapMod-specific checklist evidence, or define
the exact confirmation phrase for a later hardware attempt.

WP-064-D can upload and start one reviewed 3MF artifact with separate exact
human confirmations. It does not operate on SwapMod candidate ids and does not
execute extracted plate-change G-code.

# Scope

In scope:

- Add default-off config for SwapMod canary preflight.
- Add read-only/preflight endpoints:
  - `GET /api/v1/plate-change-3mf/swapmod-canary-preflight/status`
  - `POST /api/v1/plate-change-3mf/swapmod-canary-preflight/packages`
- Accept one redacted WP-065 dry-run result and one candidate id.
- Require one target printer id, A1 Mini model-family scope, all checklist
  fields true, and exact confirmation phrase:
  `CONFIRM_SWAPMOD_CANARY_PREFLIGHT <printer_id> <candidate_id> <line_range_hash>`.
- Return a redacted package id, selected candidate summary, stop conditions,
  no-execution flags, and zero side-effect sentinels.
- Unit, API, architecture, harness, Make target, architecture doc, runbook, and
  Work Package updates.

Out of scope:

- Real printer commands, direct MQTT, FTPS, or raw `send_gcode`.
- Printer upload, print start, pause, cancel, resume, queue dispatch, scheduler
  dispatch, batch, or next-print automation.
- Bed-ready mutation or physical actuator control.
- Arbitrary raw G-code request/response fields.
- Real A1 Mini canary execution.
- Software retry or resume after restart.
- Committed generated 3MF/G-code artifacts, printer IPs, access codes, serial
  numbers, tokens, logs, or customer data.

# Architecture Boundaries

WP-066 is a canary preflight boundary only. It consumes redacted WP-065 summary
data and produces redacted review evidence. It must not import or call Bambuddy
printer manager, Bambu MQTT, FTPS helpers, queue or scheduler dispatch paths,
ERP, Obico, or bed automation mutation paths.

The output package is not executable approval. A later real canary Work Package
must still define a separate, human-gated hardware procedure with one printer,
one attempt, no retry, exact confirmations, emergency stop/power cutoff, and no
next print before bed READY.

# Decisions

- WP-066 packages redacted candidate evidence only. It does not execute the
  candidate.
- The exact confirmation phrase binds printer id, candidate id, and candidate
  line range hash.
- A1 Mini scope is required explicitly in this Work Package.
- The future real canary remains a separate Work Package.

# Failure and Recovery

There is no migration. Rollback is a file-level revert of the WP-066 config,
schema, route, service, tests, Make target, docs, and runbook changes.

Operational rollback is to leave `FARM_SWAPMOD_CANARY_PREFLIGHT_ENABLED=false`.
