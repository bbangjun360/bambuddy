# Purpose

Create a safe 3MF post-processing prototype for future plate-change automation.
WP-064-A inspects bounded test 3MF artifacts, identifies internal G-code
candidate paths and symbolic insertion points, and returns a redacted plan. It
does not upload to printers, start prints, send MQTT, use FTPS, execute G-code,
dispatch a queue item, or mutate ERP, Obico, or bed automation state.

# Scope

In scope:

- Add a default-off, dry-run-only 3MF post-processing planner service.
- Accept only local 3MF paths inside controlled test/temp roots.
- List internal 3MF entries and identify internal G-code candidate paths.
- Return symbolic candidate blocks, insertion points, safety notes, sentinel
  counters, and a redacted diff summary.
- Optionally create a modified 3MF only when output artifact creation is
  explicitly enabled and the output directory is inside a controlled temp root.
- Add read/plan-only API endpoints if they remain blocked by safe runtime flags.
- Add focused tests and Make targets for WP-064-A.
- Add architecture docs and this execution record.

Out of scope:

- Real printer command execution.
- Printer upload or print start.
- Direct Bambu MQTT, FTPS, or arbitrary G-code endpoints.
- Raw command or raw editable G-code request bodies.
- Queue dispatch, scheduler dispatch, ERP writes, Obico mutation, bed automation
  mutation, UI work, migrations, production dependencies, or hardware canary
  execution.
- Committing raw 3MF files, raw G-code files, extracted full G-code, model
  geometry, printer identifiers, access codes, tokens, IPs, or customer data.

# Architecture Boundaries

Bambuddy remains the future authority for printer state-changing commands, but
WP-064-A adds no state-changing command path. The prototype is a local artifact
planner only. It may parse ZIP members and read bounded internal G-code content
for symbolic markers, but it must never return raw G-code text, accept editable
G-code text, or connect to printer, queue, scheduler, ERP, Obico, or bed
automation modules.

The public API surface, if present, is read/plan-only:

- `POST /api/v1/plate-change-3mf/postprocess-plans`
- `GET /api/v1/plate-change-3mf/status`

# Decisions

- WP-064-A will use synthetic 3MF fixtures generated in tests only.
- The planner will redact source filenames and never expose absolute paths or
  raw G-code content in responses.
- Output artifacts are disabled by default and require both a runtime setting
  and an explicit service/request flag.
- Output artifacts, when enabled in tests, must be written only under a test
  temp directory or local ignored temp root.
- No library row, archive row, queue item, scheduler action, ERP record, Obico
  record, or bed automation record is created by WP-064-A.
- The optional output artifact does not edit internal G-code in WP-064-A; it
  copies the 3MF and adds a redacted prototype manifest at
  `Metadata/bambuddy_plate_change_postprocess_plan.json`.

# Failure and Recovery

There is no migration or durable state. Rollback is a file-level revert of the
WP-064-A service, schema, route, settings, tests, Make targets, docs, and this
ExecPlan.

Stop and revise if implementation requires live printer transport, FTPS, MQTT,
queue dispatch, scheduler dispatch, ERP/Obico/bed mutation, an arbitrary G-code
endpoint, raw editable command input, a production dependency, UI changes, or a
core patch outside the recorded scope.

# Risks and Human Gates

Remaining risks:

- Symbolic insertion candidates may not correspond to safe firmware behavior.
- A modified 3MF artifact can still be unsafe if reviewed poorly or used outside
  this prototype.
- Dry-run artifact planning is not evidence that physical plate-change
  automation is safe.

Future gates:

- WP-064-B may add deterministic synthetic insertion tests.
- WP-064-C may add human-reviewed real sample output generation with sanitized
  evidence.
- Printer upload/start remains out of scope until a separate approved workpack.

# Outcomes

WP-064-A now exposes a safe 3MF post-processing planner behind disabled-by
default config flags. It accepts only controlled local/temp 3MF paths, lists
internal ZIP entries, identifies internal `.gcode` files, detects the embedded
printer model family when present, and returns symbolic candidate blocks,
insertion points, safety notes, side-effect sentinels, and a redacted diff
summary.

The API surface is read/plan-only:

- `POST /api/v1/plate-change-3mf/postprocess-plans`
- `GET /api/v1/plate-change-3mf/status`

The prototype does not expose raw editable G-code input, does not emit raw
G-code in responses, does not add upload/start/execution endpoints, and does not
import live printer, MQTT, FTPS, queue, scheduler, ERP, Obico, or bed automation
mutation modules.
