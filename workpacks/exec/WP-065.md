# Purpose

Add a default-off SwapMod 3MF dry-run workflow that compares one original A1
Mini 3MF with one SwapMod-generated 3MF, summarizes candidate plate-change
blocks for human review, and simulates the future post-print workflow without
hardware side effects.

This Work Package does not send printer commands, upload files, start prints,
clear plate gates, dispatch queue items, call the scheduler, connect to Bambu
MQTT or FTPS, mutate ERP/Obico/bed automation state, expose arbitrary raw
G-code, retry, or resume physical actions after restart.

# Current Behavior

WP-064-D can upload and start one reviewed 3MF artifact under explicit human
supervision. It does not extract SwapMod G-code, react to print completion,
control a plate swap, verify bed READY, or start the next print.

Existing Bambuddy queue G-code injection can insert configured start/end
snippets into a 3MF before upload, but it is not an original-finish-triggered
SwapMod extraction workflow.

# Scope

In scope:

- Add default-off dry-run config for SwapMod 3MF analysis.
- Add read-only dry-run endpoints:
  - `GET /api/v1/plate-change-3mf/swapmod-dry-run/status`
  - `POST /api/v1/plate-change-3mf/swapmod-dry-run/plans`
- Accept one original `.3mf` and one SwapMod `.3mf` under controlled roots.
- Read internal `.gcode` members only to compute redacted summaries.
- Return candidate block ids, candidate kinds, line counts, line range hashes,
  command-family counts, and safety notes.
- Return a dry-run workflow trace for the future real canary:
  `WAIT_ORIGINAL_FINISH`, `EXTRACT_REVIEWED_SWAP_BLOCK`,
  `MANUAL_REVIEW_REQUIRED`, `WOULD_SEND_ALLOWLISTED_SEQUENCE`,
  `WOULD_START_NEXT_PRINT`.
- Unit, API, architecture, harness, Make target, architecture doc, runbook, and
  Work Package updates.

Out of scope:

- Real printer commands, direct MQTT, FTPS, or raw `send_gcode`.
- Printer upload, printer start, queue dispatch, scheduler dispatch, batch, or
  next-print automation.
- Bed-ready mutation or physical actuator control.
- Arbitrary raw G-code request/response fields.
- Real A1 Mini canary execution.
- Software retry or resume after restart.
- Committed generated 3MF/G-code artifacts, printer IPs, access codes, serial
  numbers, tokens, logs, or customer data.

# Architecture Boundaries

WP-065 is a planning and review boundary only. It may read local controlled 3MF
fixtures or reviewed samples and compute deterministic redacted summaries. It
must not import or call Bambuddy printer manager, Bambu MQTT, FTPS helpers,
queue or scheduler dispatch paths, ERP, Obico, or bed automation mutation paths.

Ambiguous extraction remains manual-review only and never becomes executable
approval. A future WP-066 may add a separate human-gated physical canary using
one allowlisted candidate id, one printer, one attempt, exact confirmation
phrases, no retry, and no next print before bed READY.

# Decisions

- WP-065 uses exact duplicate-original matching only. Fuzzy real-sample matching
  is deferred until after this boundary is proven.
- The response never returns raw G-code. It returns stable hashes and command
  family counts for review.
- The future real canary is intentionally a separate Work Package.

# Failure and Recovery

There is no migration. Rollback is a file-level revert of the WP-065 config,
schema, route, service, tests, Make target, docs, and runbook changes.

Operational rollback is to leave `FARM_SWAPMOD_3MF_DRY_RUN_ENABLED=false`.
