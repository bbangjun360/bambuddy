# Purpose

Define the allowlisted Bambuddy-native plate-change command sequence plan for
A1 mini without sending any real printer command.

# Current Behavior

WP-063-A added `POST /api/v1/plate-change/dry-run-commands` and
`GET /api/v1/plate-change/status` behind default-disabled, dry-run-only,
one-printer, exact human approval gates. Before WP-063-B, the route accepted only
`supervised_plate_change_v1` and returned an auditable dry-run record with action
fields set to `None` and sentinels at zero, but it did not include a concrete
`command_plan` result.

Existing Bambuddy live command paths were inspected:

- `backend/app/services/bambu_mqtt.py` publishes `project_file`, stop, pause,
  resume, and internal generic command-emitter payloads over MQTT.
- `backend/app/services/printer_manager.py` wraps active MQTT clients for
  `start_print()` and `stop_print()`.
- `backend/app/api/routes/printers.py` owns existing stop, pause, resume,
  bed-jog, and home-axes routes.
- `backend/app/services/print_scheduler.py` and
  `backend/app/services/background_dispatch.py` upload files over FTPS before
  calling `printer_manager.start_print()`.
- `backend/app/api/routes/print_queue.py` can stop an active queue item through
  `printer_manager.stop_print()` and otherwise uses scheduler gates.
- WP-063 tests already patch common live-command and downstream side-effect
  boundaries and assert dry-run sentinels remain zero.

# Scope

In scope:

- Replace the placeholder WP-063 command sequence with A1 mini enum sequence ids.
- Add a plan-only `command_plan` result for approved dry-run requests.
- Keep command plan content symbolic or redacted, with no raw editable command
  input and no live execution support.
- Add service, API, and architecture tests for enum-only sequence planning and
  side-effect boundaries.
- Update WP-063 architecture and canary docs.

Out of scope:

- Live MQTT, FTPS, printer-manager, queue, scheduler, ERP, Obico, or bed
  automation calls.
- Raw command text in request or response.
- A generic arbitrary command endpoint.
- Hardware approval or physical canary execution.
- UI changes, migrations, or new production dependencies.

# Architecture Boundaries

Bambuddy remains the only future owner for printer state-changing commands. This
Work Package adds only planning data. It must not import or call live command
transports or downstream mutation services. `real_execution_supported` must
remain `false`, and the plan must remain one-printer and human-confirmed.

# Decisions

- The new allowed sequence ids are `A1_MINI_PLATE_CHANGE_DRY_RUN` and
  `A1_MINI_PLATE_CHANGE_CANDIDATE_V1`.
- `A1_MINI_PLATE_CHANGE_DRY_RUN` returns `PLAN_ONLY` with a single no-command
  boundary marker.
- `A1_MINI_PLATE_CHANGE_CANDIDATE_V1` returns `DRY_RUN_PLANNED` with symbolic
  candidate steps only.
- `real_execution_supported=false` is part of every command plan.
- Raw command text is not accepted or returned.
- WP-063-B does not keep the old placeholder `supervised_plate_change_v1` in the
  active API enum.

# Failure and Recovery

There is no migration or durable state. Rollback is a file-level revert of the
WP-063-B code, tests, docs, and this ExecPlan. If any sentinel becomes non-zero,
any raw command text is accepted, or any live command path is called, stop and
revert before hardware canary work continues.

# Risks and Human Gates

Remaining risks:

- Symbolic candidate steps are not firmware-validated commands.
- Physical A1 mini behavior is not proven by dry-run planning.
- A later Work Package must provide reviewed exact command content, a dedicated
  printer-manager executor, canary evidence, emergency stop path, and manual
  recovery plan before live execution.
