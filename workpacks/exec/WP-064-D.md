# Purpose

Add a supervised physical canary boundary for WP-064 that permits exactly one
reviewed 3MF artifact to be uploaded to one canary printer and started once,
under explicit human supervision.

This Work Package adds a narrow hardware boundary, disabled by default and
fully mocked in tests. It does not add queue, scheduler, batch, multi-printer,
automatic retry, arbitrary raw G-code, or raw command execution paths.

# Scope

In scope:

- Add config flags:
  - `FARM_PLATE_CHANGE_3MF_PHYSICAL_CANARY_ENABLED=false`
  - `FARM_PLATE_CHANGE_3MF_ALLOW_PRINTER_UPLOAD=false`
  - `FARM_PLATE_CHANGE_3MF_ALLOW_PRINT_START=false`
  - `FARM_PLATE_CHANGE_3MF_CANARY_SINGLE_PRINTER_ONLY=true`
  - `FARM_PLATE_CHANGE_3MF_CANARY_REQUIRE_HUMAN_CONFIRMATION=true`
  - `FARM_PLATE_CHANGE_3MF_CANARY_DISABLE_AUTO_RETRY=true`
  - `FARM_PLATE_CHANGE_3MF_CANARY_MAX_STARTS=1`
- Add allowed canary endpoints:
  - `GET /api/v1/plate-change-3mf/canary-status`
  - `POST /api/v1/plate-change-3mf/canary-upload`
  - `POST /api/v1/plate-change-3mf/canary-start`
- Require the artifact path to resolve under the configured output root and
  outside the repository.
- Require exact artifact SHA-256 match.
- Require separate exact upload and start confirmation phrases.
- Require one printer, one artifact, one prior successful upload record, and one
  start attempt.
- Require all checklist fields before start.
- Block uncertain printer state before start.
- Unit, integration, architecture, harness, Make target, architecture doc,
  runbook, and Work Package updates.

Out of scope:

- Raw G-code or arbitrary command endpoints.
- Endpoint names containing `raw-command`, `send-gcode`, `execute-gcode`,
  `bulk-start`, `schedule`, `queue`, or `auto-run`.
- Queue, scheduler, batch, multi-printer, automatic retry, or software resume.
- Direct external-module MQTT or FTPS control.
- ERP, Obico, bed automation, inventory, or accounting mutation.
- CI or test access to real printers or hardware.
- Committed generated 3MF/G-code artifacts, real printer IPs, access codes,
  serial numbers, tokens, logs, or customer data.

# Architecture Boundaries

The canary remains Bambuddy-owned. The service layer owns policy, state, path
validation, hash validation, confirmation phrases, checklist validation, and the
single-start gate. Printer operations are injected behind a narrow adapter so
unit and API tests use mocks only.

The route adapter uses existing Bambuddy printer upload/start abstractions only
after every feature flag and human gate is enabled. It does not enqueue work,
call the scheduler, retry, or expose raw G-code.

Canary state is process-local by design. A restart forgets any prior canary
upload record and never automatically resumes an uncertain physical action.

# Decisions

- The canary endpoints are separate from postprocess planning but share the
  `/api/v1/plate-change-3mf` API boundary.
- The upload phrase never authorizes start; start requires a separate phrase.
- Start checks the current printer state and accepts only a known idle state.
- A1/A1 Mini can remain in terminal `FINISH` after a completed job; the
  canary treats `FINISH` as known idle only when no active `gcode_file` is
  present and all human checklist gates are true.
- A1 Mini swapmod artifacts can report a second `RUNNING` cycle after the
  first 0-100% progress pass while the printer swaps the plate and starts the
  next output; monitor `state`, active file, and `error_code` rather than
  treating progress reset alone as failure.
- The single start attempt is consumed before the start adapter call, so failure
  is not retried automatically.
- Canary upload/start state is not persisted across restart.

# Failure and Recovery

There is no migration. Rollback is a file-level revert of the WP-064-D config,
schema, route, service, tests, Make target, docs, and runbook changes.

Operational rollback is to disable any canary flag:

- `FARM_PLATE_CHANGE_3MF_PHYSICAL_CANARY_ENABLED=false`
- `FARM_PLATE_CHANGE_3MF_ALLOW_PRINTER_UPLOAD=false`
- `FARM_PLATE_CHANGE_3MF_ALLOW_PRINT_START=false`

# Risks and Human Gates

- Simulation and mocked tests are not evidence that the physical printer is safe.
- A named operator must be present with the printer visible, emergency stop
  ready, and power cutoff ready.
- The artifact must be reviewed and hash-verified before upload.
- Any uncertain printer state blocks start and requires manual review.
