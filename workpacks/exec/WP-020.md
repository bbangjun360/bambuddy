# Scope

In scope:

- Prometheus harness configuration.
- Grafana provisioning and a minimal dashboard definition.
- Observability-specific Compose override/profile.
- Harness tests for metrics, scrape configuration, Grafana provisioning, mock
  failure metrics, and synthetic secret redaction.
- A deterministic resettable mock-service failure scenario.
- `workpacks/exec/WP-020.md` evidence updates.
- Makefile targets only for WP-020 observability commands.

Out of scope:

- Bambuddy UI or frontend changes.
- Product backend behavior changes unless strictly required for metrics
  exposure.
- Printer registration, real printer connection, Bambu MQTT, Bambu FTPS,
  printer credentials, ERP, Obico, PrintFlow, bed automation, scheduler,
  costing, Bambu Studio, InfluxDB, and production alerting integrations.

# Architecture Boundaries

- Bambuddy remains the central control plane.
- Observability services are read-only and must not control printers.
- Prometheus and Grafana observe metrics; they are not workflow engines.
- No observability service may publish MQTT commands, call printer FTPS/MQTT,
  or introduce a business-state data store.
- Bambuddy `/api/v1/metrics` remains disabled by default. The harness may
  explicitly enable it in isolated local test state for scrape validation.

# Decisions

- Use a separate `harness/docker-compose.observability.yml` override with an
  `observability` profile so the base WP-000/WP-010 harness remains stable.
- Reuse Bambuddy's existing `/api/v1/metrics` instead of adding product
  metrics code.
- Add harness-only metrics to mock-services for deterministic failure
  visibility.
- Add a harness-only observer exporter for Bambuddy health and Orca slice
  evidence so Prometheus can scrape text metrics without scraping JSON health
  endpoints.
- Keep ports configurable through `.env.harness` and `.env.harness.example`.

# Harness Changes

- Add deterministic mock-service `/metrics` output and reject unknown scenarios
  to prevent arbitrary label values.
- Add `harness/scripts/observability_exporter.py` for read-only health and Orca
  evidence metrics.
- Add `harness/scripts/observability_health.py` to validate the full local
  observability harness.
- Add `harness/tests/test_observability_wp020.py` for static config contracts,
  mock metrics, observer metrics, and secret-redaction evidence.

# Failure and Recovery

- All added services are harness-only and can be stopped with
  `make harness-down`.
- Full cleanup of observability volumes can be done with Docker Compose down
  against both harness compose files and `-v`; this deletes only isolated
  `farm_harness` volumes and requires human approval under repository rules.
- Rollback is deleting the WP-020 harness files/targets and reverting
  `.env.harness*`, `harness/mock_services.py`, and this ExecPlan.

# Risks and Human Gates

- Docker image pulls for Prometheus/Grafana may require network access.
- `make harness-reset` or any volume deletion remains a destructive action and
  requires explicit human approval.
- No hardware canary is applicable; WP-020 has no printer or actuator access.
