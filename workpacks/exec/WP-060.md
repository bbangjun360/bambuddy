# WP-060-B Supervised Real PrintFlow Canary Adapter ExecPlan

# Purpose

Prepare a human-supervised real PrintFlow canary adapter boundary while keeping
real hardware-affecting PrintFlow calls impossible by default. WP-060-B adds the
adapter seam, explicit configuration gates, exact human approval phrase checks,
single-printer restriction, mocked tests, and live-canary runbook updates.

This plan does not authorize or execute a real PrintFlow call.

# Scope

In scope:

- Default-off real PrintFlow adapter flag.
- Dry-run default-on and exact human approval gate.
- Single-printer canary restriction.
- Network-capable real adapter boundary isolated to WP-060 service code.
- A real-run API path that returns blocked/audit results unless all gates pass.
- Mocked service/API tests only; no real network or hardware calls in tests.
- Runbook updates for supervised live canary phrase, checklist, stop
  conditions, and rollback.

Out of scope:

- Executing a real PrintFlow request.
- Printer commands, printer registration, canary job execution, or dispatch.
- Direct Bambu MQTT, FTPS, or arbitrary G-code endpoints.
- Queue auto-dispatch or scheduler behavior.
- ERP submit, inventory posting, or accounting posting.
- Obico mutation.
- Unsafe `BedAutomationCycle` mutation.
- Production credentials, real endpoints, serials, IPs, customer data, or broad
  Trivy/CI/security changes.

# Architecture Boundaries

Bambuddy remains the sole control plane. The real PrintFlow adapter boundary is
a canary-only endpoint client and does not import or call printer managers,
Bambu MQTT, FTPS, queue dispatch, scheduler, ERP posting, Obico mutation, bed
automation models, or G-code paths.

The real adapter cannot be triggered by request payload alone. The route passes
settings-owned gates into `PrintFlowCanaryReadinessService.create_real_canary`.
The service returns `REAL_CANARY_BLOCKED` before constructing the adapter unless
all gates pass:

- real adapter enabled;
- global canary dry-run disabled;
- request dry-run is false;
- request audit-only is false;
- human approval is required and present;
- exact phrase `CONFIRM_REAL_PRINTFLOW_CANARY <printer_id> <job_id>` matches the
  single target printer and job;
- one target printer only;
- job id present;
- base URL and API token configured.

If any gate is missing, the adapter factory is not called and all side-effect
sentinels stay zero.

# Decisions

- Keep WP-060-B in the existing `printflow_canary` module to avoid adding a new
  dependency or touching upstream core printer code.
- Use settings-only real adapter selection; request bodies cannot choose real
  mode.
- Keep the exact human approval phrase derived from the submitted single printer
  id and job id. Boolean approval alone is not enough for the real boundary.
- Return blocked results rather than raising for missing gates so operators and
  tests receive auditable failure reasons.
- Store successful fake/real-boundary runs in memory by idempotency key for this
  boundary slice. A later physical canary must treat restart/uncertain state as
  manual review rather than automatic resume.
- Use Python standard library HTTP code for the isolated adapter boundary to
  avoid adding a production dependency.

# Harness Changes

No harness service behavior changes are required for WP-060-B. Existing harness
readiness tests remain the mock-only evidence path. New API/service tests use an
injected fake adapter and patch the route-level factory, so no test performs a
real network call.

# Failure and Recovery

If any real canary gate is missing, `create_real_canary` returns
`REAL_CANARY_BLOCKED`, records the blocking reasons, does not construct the
adapter, and leaves printer, queue, scheduler, ERP, Obico, and bed action fields
as `None` with zero sentinels.

If a later approved physical canary fails after a real request has been sent,
operators must stop rollout, preserve logs/metrics/audit evidence, disable the
real adapter, restore dry-run mode, and leave any uncertain printer or bed state
in manual review. No automatic retry or restart resume is allowed.

Rollback for this PR is file-level revert only. There is no migration and no
persistent WP-060-B table.

# Risks and Human Gates

Real hardware-affecting PrintFlow calls are forbidden in this PR. Before any
later real call, the human must first confirm:

- target printer is physically visible or actively monitored;
- bed is clear;
- emergency stop or power cutoff is accessible;
- correct filament is loaded;
- correct build plate is installed;
- no production/customer job is involved;
- job is a low-risk canary job;
- operator is ready to stop the printer manually;
- logs/telemetry are being captured;
- rollback path is known.

Only after that checklist may the release owner ask for the exact phrase:

`CONFIRM_REAL_PRINTFLOW_CANARY <printer_id> <job_id>`

No such phrase was requested or used during WP-060-B implementation.
