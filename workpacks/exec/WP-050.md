# Scope

In scope:

- A durable or equivalent simulated BedCycle domain object/model.
- Deterministic in-process simulated adapter/state transitions.
- Mock-service endpoint or harness scenario for deterministic bed automation simulation.
- Tests for success, failure, timeout, duplicate/idempotent, invalid transition, unknown physical state, restart-uncertain state, and safety guard behavior.
- Default-off feature flags: `FARM_BED_AUTOMATION_ENABLED=false` and `FARM_BED_AUTOMATION_DRY_RUN=true`.
- Observability for simulated transitions if it can remain small and synthetic.
- This ExecPlan evidence and rollback notes.

Out of scope:

- Real PrintFlow hardware control or production adapter.
- Real printer registration, printer commands, Bambu MQTT, FTPS, G-code, GPIO, serial, BLE, USB, or hardware network access.
- Scheduler changes, queue dispatch, executable job enqueueing, ERP writes/posting, Obico work, UI changes, production secrets, real customer data, and destructive migrations.

# Architecture Boundaries

- Bambuddy remains the sole control plane for printer state-changing commands.
- WP-050 simulator represents controlled bed state only; it does not start prints or enqueue executable jobs.
- The simulator must not import or call printer command paths, MQTT, FTPS, G-code, GPIO, serial, BLE, USB, or external hardware-network clients.
- Uncertain physical state and timeout outcomes become blocked or manual-review states, never implicit success.
- Duplicate events and repeated commands are idempotent and do not create additional side effects.
- Test fixtures are synthetic and must not contain secrets, real printer IPs, access codes, serials, tokens, or customer data.

# Failure and Recovery

- Failure, timeout, unknown physical state, and restart from uncertain execution must resolve to blocked or manual-review states.
- Duplicate events/commands must return the existing result and not append duplicate side effects.
- Rollback is file-level: remove WP-050 simulator module, tests, mock endpoints/scenarios, Makefile targets, and this ExecPlan. No destructive migration or hardware cleanup is expected.

# Risks and Human Gates

- Physical automation remains simulation only. Any hardware canary requires a later Work Package and human checklist.
- No production credentials or real printer endpoints may be introduced.
- If implementation requires a core printer command path patch, stop and record it in `.fuzzyline/PATCH_LEDGER.yaml` before continuing.
- If more than one service contract change is required, stop and revise scope.
