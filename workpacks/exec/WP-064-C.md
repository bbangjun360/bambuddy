# Purpose

Add local-only real-sample 3MF output review mode for WP-064. The mode allows
reviewed local generation of output 3MF artifacts from real sample files under a
configured sample root, writing outputs only under a configured output root.

This Work Package is review-only. It does not upload to printers, start prints,
send MQTT, use FTPS, queue or schedule jobs, mutate ERP/Obico/bed automation, or
execute G-code.

# Current Behavior

Baseline observed on branch `feature/wp-064-real-sample-3mf-output-review`.

Before edits, `make verify-fast` passed on 2026-06-26 KST with 70 harness tests
and 2 characterization tests.

WP-064-B provides disabled-by-default, dry-run-only synthetic 3MF inspection and
symbolic synthetic insertion under controlled temp roots. It rejects raw G-code
request fields, keeps printer upload/start/execution unsupported, and writes no
artifacts unless output creation is explicitly enabled.

# Scope

In scope:

- Add config flags:
  - `FARM_PLATE_CHANGE_3MF_REAL_SAMPLE_ROOT`
  - `FARM_PLATE_CHANGE_3MF_OUTPUT_ROOT`
  - `FARM_PLATE_CHANGE_3MF_ALLOW_REAL_SAMPLE_OUTPUT=false`
- Add explicit request fields for local review output mode.
- Require both config and request flags for real-sample output.
- Require source paths under the configured sample root or default local sample
  root.
- Require output paths under the configured output root or default local output
  root.
- Reject repository-relative output paths.
- Create output 3MF artifacts by preserving source members and adding only a
  deterministic review manifest.
- Return redacted names, source/output hashes, internal G-code paths, modified
  internal paths, preserved member count, deterministic diff summary,
  `human_review_required=true`, `not_approved_for_printing=true`, and disabled
  printer execution booleans.
- Unit, integration, architecture, harness, docs, and Make target updates.

Out of scope:

- Printer upload, printer start, MQTT, FTPS, printer-manager calls, queue or
  scheduler dispatch, ERP writes, Obico mutation, or bed automation mutation.
- Arbitrary raw G-code/body command fields.
- New endpoints named upload, start, execute, send, send-gcode, live-run, or
  raw-command.
- Executable A1 mini G-code insertion.
- Tests that use `~/workspace/plate-change-samples` or real local samples.
- Committed generated `.3mf`, `.gcode`, or `.gcode.3mf` files.

# Architecture Boundaries

The existing `POST /api/v1/plate-change-3mf/postprocess-plans` endpoint remains
the only write-producing API surface. It is still dry-run and prototype-only.
WP-064-C adds a manifest-only artifact path, not a printer execution path.

The service keeps all output artifacts local. Bambuddy remains the only future
authority for printer state-changing commands, and this Work Package adds no
printer command boundary.

# Decisions

- Real-sample review mode reuses the existing postprocess plan endpoint and adds
  no new execution endpoint.
- The request flag is `real_sample_output_review=true` and must be combined with
  `create_output_artifact=true`.
- Real-sample output writes only a deterministic review manifest at
  `Metadata/bambuddy_real_sample_output_review.json`.
- Internal G-code members are not modified in real-sample review mode.
- Output directories under the repository are rejected even if configured as an
  output root.

# Failure and Recovery

There is no migration or durable state. Rollback is a file-level revert of the
WP-064-C service, schema, route, tests, Make target, docs, and runbook changes.
Generated review artifacts are local files under the configured output root and
are not committed.

# Risks and Human Gates

- Simulation and local artifact generation are not evidence that a physical
  printer action is safe.
- Every WP-064-C output is marked `human_review_required=true` and
  `not_approved_for_printing=true`.
- A separate approved Work Package is required before any printer upload or
  print start behavior exists.
