Implement WP-030, the smallest ERP read-only integration baseline. A synthetic mock or
sandbox ERP Work Order can be fetched and converted into a Bambuddy-side review-only
production request that cannot enqueue, start, or control a printer.

# Scope

Out of scope:

  hardware actions.
- Printer dispatch, queue auto-start, scheduler, Orca, Obico, PrintFlow, bed

  customization, and Frappe app implementation.
- WP-020 worktree inspection or modification.

# Architecture Boundaries

- Bambuddy remains the central control plane and sole authority for printer
  state-changing commands.
- ERPNext and the ERP adapter never control printers and never use Bambu MQTT, FTPS, or
  G-code endpoints.
- The WP-030 import creates only review-only or blocked local data; it must not create
  executable queue entries.
- All external ERP inputs are validated before local persistence.
- Duplicate ERP Work Orders map to the same local request.
- Transient ERP HTTP failures and timeouts are visible and retryable.
- No secrets, production tokens, serial numbers, access codes, IPs, or customer data are
  introduced in fixtures, logs, snapshots, commits, or PR output.

# Failure and Recovery

- Duplicate imports must reuse the same local request.
- Missing artifact/profile mappings must produce blocked or review-only requests.
- 429, 500, auth failure, invalid payload, and timeout cases must be reported safely and
  leave retryable state where applicable.
- Timeouts must not create duplicate side effects.
- Rollback is file-level removal of WP-030 adapter, tests, mock scenarios, and any
  additive harness targets or schema additions created for this Work Package.

# Risks and Human Gates

- Harness project-name changes can affect WP-000/WP-010 expectations; update narrowly and
  preserve regression targets.
- Any migration must be additive and rollback-friendly.
- No hardware or production ERP canary is allowed in WP-030.
- No PR merge is allowed from this session.

# Outcomes

- A deterministic mock ERP Work Order can be fetched from the existing harness mock
  service.
- ERP Work Orders import into `ErpProductionRequest`, a non-executable Bambuddy-side
  review object.
- Duplicate Work Order imports preserve the same local request.
- Missing artifact and missing/unsupported profile mappings produce blocked statuses.
- Invalid payload, expired token, 429, 500, and timeout cases are recorded as
  `IMPORT_FAILED` with safe retry metadata.
- API-level tests prove imports do not create `PrintQueueItem` or `PrintLogEntry`
  records and the ERP read-only module does not reference printer command paths.
- Rollback is additive: remove the `erp_readonly` module/route/model/tests, remove the
  mock ERP scenarios and `test-erp-readonly` target, then drop the
  `erp_production_requests` table if a deployed database has already created it.
