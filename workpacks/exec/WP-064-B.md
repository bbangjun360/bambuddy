# Purpose

Extend the WP-064 3MF post-processing prototype with deterministic synthetic
insertion behavior and tests. WP-064-B inserts only a symbolic, redacted
plate-change marker block into synthetic internal G-code fixtures under
controlled temp roots.

# Scope

In scope:

- Synthetic minimal 3MF fixtures only.
- Deterministic insertion point detection in synthetic internal G-code.
- Insertion of this symbolic block only:

```text
; BAMBUDDY_PLATE_CHANGE_BLOCK_START
; symbolic_step: PLATE_CHANGE_REVIEW_REQUIRED
; symbolic_step: NO_REAL_GCODE_IN_WP_064_B
; BAMBUDDY_PLATE_CHANGE_BLOCK_END
```

- ZIP member structure preservation.
- Byte preservation for unrelated 3MF members.
- Output artifacts only under pytest temp paths or explicit controlled temp
  roots.
- Result fields describing source/output hashes, inserted block kind, modified
  member paths, preserved member count, deterministic diff summary, and disabled
  real execution support.
- Unit, integration, harness, architecture, docs, and Make target updates.

Out of scope:

- Real user sample files.
- `~/workspace/plate-change-samples` in tests.
- Printer upload, printer start, MQTT, FTPS, G-code execution, queue dispatch,
  scheduler dispatch, ERP writes, Obico mutation, or bed automation mutation.
- Arbitrary G-code or raw command endpoints.
- Executable A1 mini G-code insertion.
- Committed generated 3MF/G-code artifacts.
- CI/security weakening or unrelated WP-063/WP-064 test weakening.

# Architecture Boundaries

The service remains a disabled-by-default, dry-run-only local artifact prototype.
Bambuddy remains the sole future authority for printer state-changing commands,
and WP-064-B adds no printer command boundary. The public API remains plan-only:

- `POST /api/v1/plate-change-3mf/postprocess-plans`
- `GET /api/v1/plate-change-3mf/status`

The request schema continues to forbid extra fields, including raw G-code,
command text, and arbitrary body payloads.

# Decisions

- The deterministic synthetic insertion point is the comment marker
  `; BAMBUDDY_SYNTHETIC_PLATE_CHANGE_INSERTION_POINT` in a synthetic internal
  G-code member.
- WP-064-B output artifacts preserve the original ZIP member set and modify only
  the target internal G-code member.
- The inserted block is symbolic comment text only and contains no executable
  A1 mini G-code.
- Unsupported synthetic structures return a safe unsupported result instead of
  creating output.
- Output artifacts remain test-temp only and require both the runtime config
  flag and explicit request/service flag.

# Failure and Recovery

There is no migration or durable state. Rollback is a file-level revert of the
WP-064-B service, tests, Make target, docs, and ExecPlan changes. Temporary
output artifacts are created only under controlled temp roots and are removed by
test cleanup.

# Risks and Human Gates

Remaining risks:

- Symbolic synthetic insertion does not prove firmware-safe real-world behavior.
- Future real-sample work could still produce unsafe artifacts without careful
  human review.

Human gates:

- Human diff review is required before any future real sample output generation.
- Printer upload/start remains out of scope.
- WP-064-C may add human-reviewed real sample output generation, still local
  only.

# Outcomes

G-code member when output artifacts are explicitly allowed under a controlled
temp root. The output ZIP preserves the original member set, modifies only the
target synthetic internal G-code member, reports deterministic source/output
hashes and diff metadata, and keeps real printer upload/start/execution support
false. Required validation passed after restoring the localhost-only smoke
